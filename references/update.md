# 更新机制

> 发生了什么（台账，只追加）与我是谁（persona，重写）分开。
> 追加是熵增。活的文档靠重写。

用户说「司马迁，更新：<链接或文件>」或「司马迁，重审」时执行本文件。不做阈值判断，不做提醒。仅用户主动触发。

## 台账

文件：`materials.md`。一行一条，只追加，不改旧行（状态列除外）。

```text
- 2026-09-12 · 播客 · 「XX」第 41 期 · ./materials/podcast-41.txt · 待并入
- 2026-09-20 · 作品 · 「XX」v1.0 上线 · https://… · 已并入 v1.3.0
```

字段：日期 · 类型 · 标题 · 链接或本地路径 · 状态（`待并入` / `已并入 vX.Y.Z`）。

类型：作品 / 复盘 / 播客 / 访谈 / 测评 / 报告 / 身份变化。对不上就写最接近的一个，不要发明新类型。

## 两种更新

### 增量

一条新材料进来。

1. 读材料，按公开行为对齐过滤。
2. 按路由表定位可动的节。表外的节要动，必须单独问。
3. 以 diff 展示：每节「原文 → 拟改」。
4. 用户确认后写入 `persona-agent.md`，patch +1。
5. 全量重渲四个投影。
6. 台账该条改为 `已并入 vX.Y.Z`。文末变更记录加一行。

### 重审

仅当用户说「重审」。

1. 重读 persona + 所有 `待并入` 材料。
2. 追问 3-5 个问题，围绕身份排序、未竟之处、被材料证伪的判断。
3. **重写** `当前身份排序` / `未竟之处` / `盲区`。盲区必须重写，不允许沿用上一版。
4. 逐节 diff → 确认 → 写入，minor +1。
5. 全量重渲投影。待并入全部标为已并入。

核心定位变了：major +1，并明确告诉用户这一次改的是「我是谁」，不是「我又做了什么」。

## 路由表

agent 只能动表内的节。

| 材料类型 | persona 可动的节 | 主页可动的区 |
|---|---|---|
| 新作品 | 已知事实 · 能力模型 · 我能提供 | Work · Offer |
| 复盘文章 | 重要判断 · 决策原则 · 未竟之处 · 盲区 | Principles |
| 播客 / 访谈 | 表达风格 · 常用词汇 · 底层动机 · 校准题 | About |
| 测评 / 报告 | 能力模型 · 重要判断 · 我能提供 | Offer · Work |
| 身份变化 | 核心定位 · 当前身份排序 · 我在找 → 建议用户重审 | Hero · Seeking |

复盘文章是唯一能证实或推翻「盲区」的材料。处理它时，第一步对照现有 2–4 条盲区：证实、推翻，或写「样本仍不足」。

身份变化不要用增量硬改核心定位。先建议重审。

## 硬规则

1. **Diff 优先**。任何写入前必须逐节展示原文 → 拟改，用户确认。不可协商。
2. **身份排序只重排不追加**。条目数可以因重审而变，但增量不得往排序里堆新头衔。
3. **投影永不手改**。源变则四个投影全量重渲。
4. **隐私规则对更新同等生效**。播客里说了但公开渠道没有的，默认不写。
5. **版本号**：增量 +patch，重审 +minor，核心定位变了 +major。写在 persona frontmatter，投影头部同步。

## 版本与历史

skill 不产出独立 diff 报告。建议用户把 personal-os 目录 `git init` 为私有仓库，`git log -p persona-agent.md` 即历史。

frontmatter 只记：

```yaml
---
version: 1.3.0
updated: 2026-09-20
last_review: 2026-03-14
---
```

文末「变更记录」不超过 3 行。更早的交给 git。
