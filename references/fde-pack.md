# FDE 入场包（司马迁 · 输出三）

> 本文件即仓库 `references/fde-pack.md` 定稿。主 `SKILL.md` 加一节"输出三"指向此文件。
> 首发口号：**让 Fable 5 做你的第一任 FDE 工程师。**

---

## 核心逻辑（整个 skill 围绕这一条）

Fable 5 / GPT 5.6 这样的顶级模型，是你**请来的资深 FDE 工程师**：能力最强、按天计费、随时可能撤场——下线、限额、涨价、被替代。

FDE 的职业纪律是：**离场时留下客户自己的工程师能接管的系统**。

所以这个 skill 的产出不是给资深工程师自己看的笔记，而是**交接包**：资深驻场期间，把它替你做过的判断写成显式规则，把它替你干过的活固化成工具和模板；退场之后，你自己的工程师——**很可能是一个更便宜、更弱的模型**——拿着这套包接管日常。

一句话：模型是租来的，资产是买下的。贵的请来建系统，便宜的留下跑系统。

**由此推出本 skill 的第一设计标准：所有资产必须写到"弱模型可执行"的程度。**显式步骤、零暗示依赖、每条带示例和验收标准。写包的是天才，读包的按普通人准备——这也是好交接文档的定义。

## 这是什么（在司马迁产品里的位置）

轻列传（30 秒）给朋友圈看你；精列传（15 分钟）产出 persona-agent.md 和主页，让 AI 和人认识你；**FDE 入场包（60 分钟）**让 AI 接管你的工作现场。三份资产：认识你 → 理解你 → 接手你。

## 触发

用户说"生成我的 FDE 入场包"、"让 AI 接手我的工作"、"输出三"、"入场包"，或完成精列传后选择继续深入时。

## 输入（按证据等级收集，产出中如实标注）

1. **【证据】聊天记录导出**（最高等级，可选）：用户从 AI 工具导出的对话数据（如 Claude 的 Settings > Privacy > Export data）。有此项走完整模式。
2. **【口供】用户自述**：最近 3 个真实任务的过程描述、常用 prompt 收藏、当前项目文档、每周时间分配。
3. **继承**：已有 persona-agent.md 读取为身份骨架；没有则先跑精列传（15 分钟）或做压缩访谈。

## 两种模式

**完整模式（约 60 分钟，有导出数据，需能执行代码的 agent：Claude Code / Cowork / Codex）**

1. **脚本先行**：写脚本解析导出文件——索引、打标签、数词频。原始语料不进对话上下文，只读统计结果和抽样。这既省 token，也是隐私动作。
2. **六问挖掘**：最常用 AI 做什么（按频率排序）；哪些任务在重复；哪些指令被反复手写；哪些工作流该固化；哪些自我认知被数据证伪（直说）；接管的工程师必须知道什么。
3. **假设检验**：自述与语料冲突时以语料为准，标注"证实 / 证伪 / 样本不足"。用户以为的工作方式和实际的工作方式之间的差距，是本模式最有价值的产出。

**轻量模式（约 30 分钟，无导出数据）**：访谈 + 材料归纳。全部条目标注【口供】/【推断】，包首页写明："本包基于自述生成，建议积累聊天记录后升级为证据版。"

## 输出：fde-pack/ 交接包

```
fde-pack/
├── README.md            交接说明：证据等级 + 怎么把包喂给接管模型
├── current-context.md   工作现场：项目、目标、约束、本月优先级
├── workflows.md         高频工作流，每条标【证据/口供/推断】+ 频率 + 接管等级
├── skills/              重复任务 → 可安装 skill 草稿（一个 skill 一个稳定任务）
├── templates/           高频 prompt → 即贴模板（含填空示例）
├── routing.md           交接合同：哪些活归接管工程师，哪些要再请资深
└── handover-test.md     交接考试：3 道真实任务题 + 判分标准
```

**接管等级（workflows.md 每条必标）**：
- ✅ 可独立接管——弱模型照 skill/模板可直接执行
- ⚠ 需资深复核——弱模型出稿，强模型或本人终审
- ⛔ 升级信号——判断/品味/战略类，包里明写"这条别自己扛，去请资深"

**routing.md 是交接合同**：日常执行归接管工程师（便宜模型），判断与品味再请资深（当时最强的可用模型）。写明升级触发条件，让弱模型知道什么时候该说"这题超纲了"。

外加一张**入场包卡**（可分享图，风格同轻列传）：你的 AI 第一大用途 / 重复最多的任务 / 一句太史公式判词 + simaqian.caojuege.com。

## 交接考试（必做，且必须考接管者）

关键规则：**考试对象是用户日常要用的那个便宜模型，不是建包的资深模型。**资深自己考自己永远满分，毫无意义。

流程：从 workflows.md 取 3 个高频任务 → 开一个无历史上下文的新会话（用接管模型）→ 只喂入场包 → 让它执行 → 用户按"能直接用 / 要小改 / 不能用"打分。低于"要小改"的条目回炉：通常是包里写了暗示、漏了示例，改到弱模型能跑为止。

交接考试通过，才算交接完成。没考过的入场包只是文件夹。

## 隐私默认（比前两份资产更严格）

聊天导出常含客户信息、合同、报价、私人对话。规则：脚本本地处理，原文不进上下文；产出只写工作模式不引敏感原文；人名/公司/金额默认脱敏为角色（"某企业客户"）；家庭、健康、财务对话直接跳过不分析。生成后提醒用户通读一遍再分享。

## 方法局限（对用户诚实）

- 轻量模式捕捉的是你以为的工作方式，完整模式才能看到实际的。
- 入场包是快照不是轨迹，建议每 1–2 个月增量重跑；换了接管模型，重考一次交接考试。
- 交接的是**流程**，不是判断。品味和决策仍是你的——routing.md 里的 ⛔ 条目就是这条边界的落地。

## 写作口吻

同司马迁家族：克制、具体、有证据感。判词允许太史公式锐利，交接文档保持工程式干净。禁营销腔（赋能/颠覆/效率提升300%）。
