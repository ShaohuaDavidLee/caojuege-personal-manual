# FDE 入场包（司马迁 · 输出三）

> 首发口号：**让 Fable 5 做你的第一任 FDE 工程师。**

---

## 核心逻辑（整个 skill 围绕这一条）

Fable 5 / GPT 5.6 这样的顶级模型，是你**请来的资深 FDE 工程师**：能力最强、按天计费、随时可能撤场——下线、限额、涨价、被替代。

FDE 的职业纪律是：**离场时留下客户自己的工程师能接管的系统**。

所以这个 skill 的产出不是给资深工程师自己看的笔记，而是**交接包**：资深驻场期间，把它替你做过的判断写成显式规则，把它替你干过的活固化成工具和模板；退场之后，你自己的工程师——**很可能是一个更便宜、更弱的模型**——拿着这套包接管日常。

一句话：模型是租来的，资产是买下的。贵的请来建系统，便宜的留下跑系统。

**第一设计标准：所有资产写到"弱模型可执行"的程度。**显式步骤、零暗示依赖、每条带示例和验收标准。写包的是天才，读包的按普通人准备——这也是好交接文档的定义。

## 在司马迁产品里的位置

轻列传（30 秒）给朋友圈看你；精列传（15 分钟）产出 persona-agent.md 和主页，让 AI 和人认识你；**FDE 入场包（60 分钟）**让 AI 接管你的工作现场。三份资产：认识你 → 理解你 → 接手你。

## 触发

用户说"生成我的 FDE 入场包"、"让 AI 接手我的工作"、"输出三"、"入场包"，或完成精列传后选择继续深入时。

## 输入（按证据等级收集，产出中如实标注；**默认不访谈**）

1. **【证据】聊天记录导出**（最高等级）：用户从 AI 工具导出的对话数据（如 Claude 的 Settings > Privacy > Export data）。有此项走完整模式。
2. **【口供+】模型记忆导出**（次优，零打字成本）：没有聊天导出时，先把下面这段给用户，让 TA 粘给自己长期使用的模型（ChatGPT / Claude / Kimi / 豆包等），把返回结果作为输入：

   ```
   把你记忆中关于我的全部内容，完整导出为 Markdown。
   分「事实 / 偏好 / 项目 / 边界」四类，要全量，不要总结，不要美化。
   最后标注：哪些是你确定的，哪些是你推断的。
   ```

3. **【口供】已有材料**：常用 prompt 收藏、当前项目文档、最近 3 个真实任务的过程记录。
4. **继承**：已有 persona-agent.md 读取为身份骨架。

**访谈只是兜底**：以上全部拿不到时才访谈，且不超过 5 问。访谈是 60 分钟预算里最贵的部分，能导出就不要问。

## 两种模式

**完整模式（约 60 分钟，有聊天记录导出，需能执行代码的 agent：Claude Code / Cowork / Codex）**

1. **脚本先行**：写脚本解析导出文件——索引、打标签、数词频。原始语料不进对话上下文，只读统计结果和抽样。这既省 token，也是隐私动作。
2. **六问挖掘**：最常用 AI 做什么（按频率排序）；哪些任务在重复；哪些指令被反复手写；哪些工作流该固化；哪些自我认知被数据证伪（直说）；接管的工程师必须知道什么。
3. **假设检验**：自述与语料冲突时以语料为准，标注"证实 / 证伪 / 样本不足"。用户以为的工作方式和实际的工作方式之间的差距，是本模式最有价值的产出。

**轻量模式（约 30 分钟，无聊天导出）**：模型记忆导出 + 材料归纳，不默认访谈。全部条目标注【口供】/【推断】，包首页写明："本包基于记忆与自述生成，建议积累聊天记录后升级为证据版。"

## 覆盖范围声明（README 必写）

包只反映它看得见的现场。README 开头必须写明：基于哪个数据源（哪个工具的导出/记忆）、哪个时间段、哪个工作现场（个人全局 / 某个 agent 的 workspace / 某个项目），以及**明确不覆盖什么**。同一个人在不同现场跑出不同的包是正常的，混起来才是事故。

## 输出：fde-pack/ 交接包

**必产四件：**

```
fde-pack/
├── README.md            覆盖范围 + 证据等级表 + 怎么喂给接管模型
├── workflows.md         高频工作流，每条标【证据/口供/推断】+ 频率 + 接管等级
├── handover-test.md     交接考试（默认一题，见下）
└── fde-pack-all.md      单文件编译视图：以上全部 + 选产内容合并为一个文件，
                         聊天界面用户一次粘贴即可交接。文件夹是源，此文件是视图。
```

**按证据量选产（撑不起就不产，宁缺毋滥）：**

```
├── current-context.md   工作现场：项目、目标、约束（材料充分时）
├── routing.md           交接合同：哪些归接管工程师，哪些再请资深（工作流≥5条时）
├── skills/              只收 ✅ 级工作流，一个 skill 一个稳定任务；⚠ 级留在 workflows.md
└── templates/           只留"填空即发"型模板；流程型的归 skill，不重复造
```

**接管等级（workflows.md 每条必标）**：
- ✅ 可独立接管——弱模型照 skill/模板可直接执行
- ⚠ 需资深复核——弱模型出稿，强模型或本人终审
- ⛔ 升级信号——判断/品味/战略类，包里明写"这条别自己扛，去请资深"

外加一张**入场包卡**（可分享图，风格同轻列传）：你的 AI 第一大用途 / 重复最多的任务 / 一句太史公式判词 + simaqian.caojuege.com。

## 交接考试（默认一题，考的是接管者）

关键规则不变：**考试对象是用户日常要用的那个便宜模型，不是建包的资深模型。**资深自己考自己永远满分。

**默认（一题）**：取最高频的 ✅ 级工作流出一道真实任务题，在 handover-test.md 里写成**现成可粘贴的完整考题**（含喂包指引）。用户新开会话粘给接管模型，肉眼三档判：能直接用 / 要小改 / 不能用。"不能用"就回炉对应条目——通常是写了暗示、漏了示例。

**升级考（三题，可选）**：换接管模型时、或包大改后再跑。三道题覆盖 ✅/⚠/⛔ 各一：第三题的满分答案是接管模型主动说"这题该找资深"。

考试是交接的一部分，不是作业。一题三分钟，粘贴即考。

## 隐私默认（比前两份资产更严格）

聊天导出常含客户信息、合同、报价、私人对话。规则：脚本本地处理，原文不进上下文；产出只写工作模式不引敏感原文；人名/公司/金额默认脱敏为角色（"某企业客户"）；家庭、健康、财务对话直接跳过不分析。生成后提醒用户通读一遍再分享。

## 方法局限（对用户诚实）

- 轻量模式捕捉的是你以为的（以及模型记忆里的）工作方式，完整模式才能看到实际的。
- 入场包是快照不是轨迹，建议每 1–2 个月增量重跑；换了接管模型，重跑一次交接考试。
- 交接的是**流程**，不是判断。品味和决策仍是你的——routing.md 里的 ⛔ 条目就是这条边界的落地。
