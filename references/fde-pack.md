# FDE 入场包（司马迁 · 输出三）

> 首发口号：**让 Fable 5 做你的第一任 FDE 工程师。**

---

## 核心逻辑（整个 skill 围绕这一条）

Fable 5 / GPT 5.6 这样的顶级模型，是你**请来的资深 FDE 工程师**：能力最强、按天计费、随时可能撤场——下线、限额、涨价、被替代。

FDE 的职业纪律是：**离场时留下客户自己的工程师能接管的系统**。

所以这个 skill 的产出不是给资深工程师自己看的笔记，而是**交接包**：资深驻场期间，把它替你做过的判断写成显式规则，把它替你干过的活固化成工具和模板；退场之后，你自己的工程师——**很可能是一个更便宜、更弱的模型**——拿着这套包接管日常。

一句话：模型是租来的，资产是买下的。贵的请来建系统，便宜的留下跑系统。

**第一设计标准：所有资产写到"弱模型可执行"的程度。**显式步骤、零暗示依赖、每条带示例和验收标准。

## 在司马迁产品里的位置

轻列传（30 秒）给朋友圈看你；精列传（15 分钟）产出 persona-agent.md 和主页，让 AI 和人认识你；**FDE 入场包**让 AI 接管你的工作现场。三份资产：认识你 → 理解你 → 接手你。

## 触发

用户说"生成我的 FDE 入场包"、"让 AI 接手我的工作"、"输出三"、"入场包"，或完成精列传后选择继续深入时。

## 两种输出方式（先问用户选哪种，默认轻量）

**轻量输出（即刻，零门槛）**：不需要导出任何文件。建包 agent 基于**它自己已有的记忆**、当前工作区材料和 persona-agent.md 直接产出。全部条目标注【口供】/【推断】，README 写明："本包基于 agent 记忆与现有材料生成，建议之后用聊天记录导出升级为证据版。"适合第一次体验，或在长期使用的 agent 里顺手生成。

**全量输出（约 60 分钟，证据级）**：引导用户导出聊天记录（Claude：Settings > Privacy > Export data；其他工具类似），放进 `./export/`，用能执行代码的 agent（Claude Code / Cowork / Codex）在本地跑：

1. **脚本先行**：写脚本做索引、打标签、数词频。原始语料不进对话上下文，只读统计结果和抽样。
2. **六问挖掘**：最常用 AI 做什么（按频率排序）；哪些任务在重复；哪些指令被反复手写；哪些工作流该固化；哪些自我认知被数据证伪（直说）；接管的工程师必须知道什么。
3. **假设检验**：自述与语料冲突时以语料为准，标注"证实 / 证伪 / 样本不足"。你以为的工作方式和实际的工作方式之间的差距，是全量输出最有价值的产出。

**隐私铁律（两种方式都适用，README 必写）**：你的记忆、导出文件和聊天原文，永远只在**你本地、你自己的 agent** 中处理。司马迁只是一份方法（开源的 skill 文本），不接收、不上传、不存储你的任何数据。

访谈只是兜底：记忆、材料都拿不到时才问，不超过 5 问。

## 覆盖范围声明（README 必写）

包只反映它看得见的现场。README 开头必须写明：基于哪个数据源（哪个工具的记忆/导出）、哪个时间段、哪个工作现场（个人全局 / 某个 agent 的 workspace / 某个项目），以及**明确不覆盖什么**。同一个人在不同现场跑出不同的包是正常的，混起来才是事故。

README 还必须包含一张**带注释的文件树**（每个文件后跟一句"干什么用"），让人 10 秒看懂包里有什么——结构图本身就是交接的一部分。

## 输出：fde-pack/ 交接包（编号即阅读顺序）

```
fde-pack/
├── 00_README.md           先读：覆盖范围、隐私声明、带注释文件树、怎么喂给接管模型
├── 01_analysis-report.md  使用分析报告：六问答案 + 证伪发现 + 建议固化的 skill 清单——给「人」看的洞察
├── 02_context.md          工作现场：项目、目标、约束（材料充分时才产）
├── 03_workflows.md        高频工作流：每条标【证据/口供/推断】+ 频率 + 接管等级
├── 04_routing.md          交接合同：日常归接管模型，判断再请资深（工作流≥5条时才产）
├── 05_skills/             只收 ✅ 级工作流，一个 skill 一个稳定任务（撑不起就不产）
├── 06_templates/          只留"填空即发"型模板；流程型的归 skill，不重复造
└── fde-pack-all.md        单文件编译视图：全部内容合并，聊天界面一次粘贴即交接
```

包里有两类文件，README 里说清楚：**00/01 是给人看的**（尤其 01 使用分析报告——它回答"你到底怎么在用 AI"，常常是用户觉得最值的一份）；**02–06 和 all 是给接管模型用的**。轻量输出至少产 00、01、03、all 四件；全量输出全产。

**接管等级（03_workflows.md 每条必标）**：
- ✅ 可独立接管——弱模型照 skill/模板可直接执行
- ⚠ 需资深复核——弱模型出稿，强模型或本人终审
- ⛔ 升级信号——判断/品味/战略类，包里明写"这条别自己扛，去请资深"


## 交付形态（让交接像一次正式交付）

完成后打包 `fde-pack-YYYYMMDD.zip`，按顺序呈现两件：**zip（存档与转发）→ fde-pack-all.md（马上能用）**。先给包，再给钥匙。

不设考试。想验证，就把包喂给日常用的便宜模型跑一个真实任务，顺手把不顺的条目改掉——验证是使用的副产品，不是仪式。

## 隐私默认（比前两份资产更严格）

聊天导出常含客户信息、合同、报价、私人对话。规则：脚本本地处理，原文不进上下文；产出只写工作模式不引敏感原文；人名/公司/金额默认脱敏为角色（"某企业客户"）；家庭、健康、财务对话直接跳过不分析。生成后提醒用户通读一遍再分享。

## 方法局限（对用户诚实）

- 轻量输出捕捉的是 agent 记忆里的你，全量输出才能看到实际的你；两者的差距本身就有信息量。
- 入场包是快照不是轨迹，建议每 1–2 个月增量重跑；换了接管模型，拿一个真实任务试跑一次。
- 交接的是**流程**，不是判断。品味和决策仍是你的——04_routing.md 里的 ⛔ 条目就是这条边界的落地。
